# 나중에 볼 것 (보류 목록)

스킬·인챈트·속성·무기를 정리할 때 다시 꺼낼 항목들. 숫자는 테스트 서버(`test` 브랜치) 기준.
기준 `426d349` 이후 확정 버그를 수정한 상태로 갱신했습니다. 아래 기존 DPS 수치는 이전 관찰값이며 이번 수정본의 새 측정값으로 해석하지 않습니다. 공격력 곡선·공격 계수·강화 확률·경제 밸런스는 그대로입니다.

## 스킬·인챈트 정리 때
- **증폭 구조(합의)**: 피해 증가 +% · 받는 피해 증가 +%(적 약화) · 공속 +% 는 각 통 안에서 **더하고**, 통끼리 곱한다. `최종 피해 ×` 는 효과 하나하나가 독립 곱셈(예전 난잡한 산식과 같음)이라 **도구로만 남기고 가급적 쓰지 않는다**(극 투자 보상 같은 특별한 경우만). 능력치별 체감 곡선은 「증폭 계산 그래프」 참고.
- **오류·메아리 피해 종류**: 원래 타격의 피해를 복사하는데(방어·치명타 포함) 딜량표에는 항상 "마법"으로 기록됨 → 원래 타격 종류를 따라가게.
- **피해 종류 판별 방식**: 공격 이름 글자로 판별(`DTYPE_MAGIC`, `ELEM_SRC`). 「처치 폭발 (칼날 속성)」이 이름 때문에 속성 규칙을 탐 → 공격마다 피해 종류·사용 공격력을 직접 지정.
- **마검과 치명타**: 물리 기본 공격이 없어 치명타가 안 나는데, 예리함·달·무지개가 있으면 일시정지·스펙에 치명타 %가 표시되고, 예리함 인챈트도 계속 제시됨.
- **성기사**: 성역·심판의 빛이 마법(마공 0.7)이 되면서 DPS −20~27% → 물공 계수 + 마법 피해(변환) 후보.
- **암살자**: 치명 보너스(+25%, 3배) 제거로 DPS −23~26%.
- **마검**: 모든 피해에 붙던 치명타 12%가 빠져 −15%.
- **물리 스킬을 얻은 마검**: 검기 등이 물공 0.4로 들어감. 「몬스터 폭발 유도」는 물리 직업이 마공 비율로 계산됨.
- **증폭 배율 정리**: 같은 종류는 더하기, 다른 종류는 곱하기. 대폭발·피의 회오리가 "모든 피해"에 붙음, 톱날이 지속 피해 틱도 셈.
- **긴 칼날**: 비도술사(단검 던지기·칼날 비)와 검기에는 효과 없음. 모든 직업에게 제시됨.
- **공통 검의 연속 공격**: `twice` Lv1부터 앞뒤 베기가 고정이라 Lv2·★3에도 추가 효과가 없지만 카드는 계속 제시됨. 수치/제시 정책을 정해야 하므로 아직 변경하지 않음. 비도술사의 추가 투척 개수 설명만 수정됨.
- **직업 간 DPS 격차**: +25, 카드 없음, 허수아비 1마리 기준 비도술사 ~8.6k, 화염술사 ~7.5k, 뇌전술사·암살자 ~5.5k, 성기사 ~3.5k, 광전사 ~2.8k.

- **한 번 맞힐 때 여러 종류 피해 (온힛)**: 예) 물리 100% + 마법 30% + 고정 10%. `svHit` 를 여러 번 부르지 말고 한 번의 타격 안에서 피해 조각을 각각 계산할 것 — 조각마다 자기 방어를 적용하고, 속성 발동·필살 게이지·칼날 비 카운트·흡혈·메아리 같은 "맞혔을 때" 효과는 타격당 1번만. 치명타가 어느 조각에 붙는지, 숫자를 조각별로 띄울지(색이 다르게 겹쳐 뜸) 정하기.
- 플레이어가 받는 고정 피해가 철갑 등 피해 감소를 무시할지 정하기 (지금은 종류 상관없이 감소 적용).

## 속성 정리 때
- 속성 메커니즘을 따로 설계 예정. 지금은 임시로 속성 피해 = 마법, 공격력은 물공·마공 중 높은 쪽.

## 던전(스테이지) 조정 때
- 무기 공격력: +20까지 단계당 12%, 이후 10% (5단계 ×1.61) 확정.
- 목표: 후반 층당 몬스터 체력 증가 ≈ 무기 성장률 → 1강 ≈ 1층, 5강 ≈ 5층(보스 한 번). 지금 51층 이후 층당 ×1.33이라 강함 차이가 층수로 안 이어짐.
- 기준선: 일반 유저 +25 전후, 헤비 유저 +30(테스터 10명 중 2명이 2~3일), 엔드 +31~35. 무한 도전 최상위는 "헤비 +30 + 좋은 빌드 + 운" 기준.
- 원정 보스 콘텐츠도 여기서.

## 강화 확률·경제 조정 때
- +35가 수주~수개월 목표가 되도록 +30 이후 확률 확인 (실제 도달은 축복·타이밍·인챈트 덕에 맨손 계산보다 훨씬 빠름).
- 가호 비용이 +24 8,000 → +25 300,000 으로 37배 점프. +30 이상은 사냥 수입이 +29 기준에서 멈춤.

## 무기 정리 때
- 계열별 물리/마법 비율 `ATK_R`은 임시 값.
- 플레이어 쪽 방어(철갑 등)는 아직 물리/마법 구분 없음.

## 본서버 적용 때
- 같이 하기 프로토콜 버전 17 (화상·중독은 건 사람이 자기 능력치로 틱): 정상 로비 출발 시 버전을 확인하므로 예전 탭은 새로고침해야 함. 모든 수신 메시지에서 다른 버전을 강제로 배제하는 구조는 아님.
- 원정에도 종족 방어 성향이 적용됨(원정에 방어가 처음 생김).

## 같이 하기 손볼 것
- 방장의 히트스톱(`B.hs`, 엘리트·보스 처치 때)이 같이 하는 필드 전체를 멈춤: 다른 사람에게는 몬스터가 잠깐 얼어붙어 보임.
- 몬스터 총알에 맞을 때 밀려남이 다름: 내 화면에서 맞으면(방장) 넉백 없음, 방장이 판정해 보내준 피격(친구)은 7px 밀림.
- 가시 갑옷이 방장이 아닌 사람에게는 작동 안 함 (스킬 정리 때 같이).
- **피해·피격 확인 응답**: `MP.hits`·`hu`는 보낸 뒤 확인 없이 비워지고, 수신 HP는 `min(로컬, 방장값)`만 적용함. 메시지가 손실되면 차이가 남을 수 있음. 번호·ack·중복 제거와 예측 상태 조정이 필요하며, 통신 형식을 바꾸면 `MP_VER`도 올릴 것. 실제 전달 실패 빈도와 두 기기 재현은 미검증.
- **참가자·메시지 검증**: 시작/층/월드/피해 메시지가 신뢰하는 발신자·경기 소속·버전·epoch 범위와 배열 크기·유한수·피해 상한 등을 정리할 것. 방 코드·공개 SELECT·현재 Origin 조건은 비공개 방 인증이나 실제 전투 검증을 제공하지 않음. 채팅 수신 측 빈도 제한도 별도 과제.
- **접속·호스트 이전 경계**: 구독 실패한 새 채널의 정리, 로컬 시각 기반 방장 순서와 프레임 시계 기반 timeout, 떠난 플레이어의 지속피해 수명, 새 경기의 효과 sequence/queue 초기화를 실제 SDK·복수 기기로 확인할 것. 손실된 피해와 남은 시각 효과를 같은 문제로 취급하지 않음.
- **인원수 계산**: `mpN()`은 자기 자신을 항상 1로 세므로 사망한 방장이 필드를 관리하면 실제 생존자보다 1명 많을 수 있음. 의도와 영향 확인 후 변경할 것.

## 전투 시간·표시의 남은 확인

- **`B.t` 시간 정책**: 일시정지·카드 선택·결과 화면에서도 늘어남. 저장 기록은 `enRecord()` 첫 호출 때 고정되어 결과창 표시와도 차이가 날 수 있음. 실제 플레이 시간/경과 시간 중 무엇을 순위에 쓸지 결정 전에는 변경하지 않음.
- **같은 판의 예약 마법**: 이전 판의 예약이 새 판으로 넘어가는 버그는 수정. 같은 판 일시정지·카드 선택 중에도 실제시간 `setTimeout`이 추가 구체를 만들며, 프레임 시계·테스트 속도와 시간이 다름. 정지 정책은 별도 결정.
- **공격 주기 표시**: `svCd()`는 다음 공격 대기시간이며 근접 공격은 이전 동작 종료도 기다림. 표시 주기 감소가 실제 DPS를 같은 비율로 올린다고 단정하지 말 것.
- **추가 판정 확인**: 대검 마지막 회전의 경계 여유로 같은 적이 추가 회전에 맞는지 위치·프레임을 통제해 검증할 것. 거리 제한 없는 연쇄 번개와 시각 타원/원형 충돌 차이는 현재 구현이며 설계 기준 없이 버그로 확정하지 않음.
- 누적 처치 기준 `halo` 회복, 미사용 `mist/orbit/danceT/time/tmax`와 일부 낡은 주석은 MECHANICS 12절에 남김.

## 저장·이전 호환성의 남은 확인

- **저장 입력 검증**: `load`/가져오기는 gold 타입과 일부 필드만 검사함. 잘못된 `ach/log/lv/보관 검` 등 전체 스키마·안전한 실패 복구는 별도 과제. 이번 `breakPend/swq`와 이전 각인 변환이 모든 잘못된 저장을 지원한다는 뜻은 아님.
- **판정 전 강화·선택 후보**: 비용을 지출한 게이지/뜸들이기 중 종료하면 그 진행 상태는 복원하지 않음. 인챈트 선택권은 저장하나 후보는 저장하지 않아 재시작 시 재추첨됨. 허용 정책을 먼저 정할 것. 파괴 판정 이후 확인 대기는 이번에 저장·복원하도록 수정함.
- **실제 옛 저장 표본**: v1 방지권 순차 변환과 `engr`만 있는 보관 검의 `eng` 변환은 구현·합성 입력으로 확인했으나 모든 역사 배포 저장 표본이 제공된 것은 아님.
- 저장 공간 부족·권한 거부 시 dirty를 유지해 다시 시도하지만 사용자 경고·내보내기 유도·용량 정책은 별도 과제. 정상 로컬 저장이 실패하면 전송 대기열 보존도 보장할 수 없음.

## 랭킹·계정 이전의 남은 확인

- **기기 간 검 소유권**: 저장 코드는 `sid`를 옮기지만 익명 인증은 별도임. 이미 다른 uid 소유로 등록된 검은 새 기기의 RLS 갱신이 거절될 수 있음. 개별 재시도로 정상 검은 전송하고 거절된 sid만 남기도록 수정했으나, 검 ID 재발급·계정 연결·소유자별 키 중 이전 정책을 정해야 함. RLS를 느슨하게 해서 해결하지 말 것.
- **최초 오프라인·인증 갱신**: 최초 `rankInit` 인증 실패 후 자동 재초기화, refresh의 일시 실패와 만료 구분, 병렬 인증 호출, 새 uid와 `RK.uid`의 일치 유지가 남아 있음. 기존 연결의 전송 재시도와 별도 문제.
- **여러 기기·탭의 순서**: 새 최고기록이 오래된 쓰기로 덮이지 않도록 서버의 단조 병합 규칙을 정할 것. 현재 큐 직렬화·새 snapshot 보존은 한 페이지 안의 문제를 해결하며 서버 전체 순서 보장은 아님.
- **코드·이름 변경과 과거 기록**: 계정 최고/파티/보유 검/이미 판매·파괴한 검이 현재 프로필을 따라갈지 당시 프로필을 보존할지 결정할 것. 캐시 범위 분리·초기 재전송이 모든 과거 행의 일괄 이동을 의미하지 않음.
- **강화 랭킹 동률**: `bs`가 info 문자열 안에 있어 서버 limit 전에 보조 순위를 적용하지 못함. 계정·파티 무한 도전의 층/점수/시간 정렬은 수정되었지만 강화 계정 표는 칼럼/서버 정렬 설계가 필요함.
- **신뢰·배포 검증**: 랭킹은 여전히 클라이언트 자기 신고이며 Origin은 보조 제한임. SQL 적용·실제 RLS·운영 업로드·두 기기 플레이는 별도 확인. 기존 `@supabase/supabase-js@2` 의존성의 정확한 버전 고정도 검토할 것.
