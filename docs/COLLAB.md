# 공동 작업 규칙 (Claude ↔ Codex)

이 프로젝트는 두 AI(Claude, Codex)가 번갈아 작업합니다. 둘은 서로 직접 연결되지 않고, **의뢰자가 zip 파일을 옮겨 주는 방식**으로 주고받습니다. 이 문서는 매번 같은 규칙입니다. 이번 과제는 `docs/codex/` 안의 과제 문서를 보세요.

## 1. 프로젝트
- 「검 강화하기」: 단일 파일 HTML 캔버스 픽셀 게임 (`index.html`). 개인 프로젝트, **전연령** 출시 예정.
- 배포: Cloudflare Pages. 본서버 `swordforge.pages.dev`(기존 이용자용) / `forgegame.pages.dev`(출시용) 둘 다 같은 코드. `test.*.pages.dev` 는 테스트 서버(`TEST_SITE`: 랭킹 기록 안 올림, 테스트룸 🧪 버튼).
- 백엔드: Supabase (랭킹, 같이 하기 실시간). `supabase_*.sql` 은 의뢰자가 SQL Editor 에서 직접 실행합니다.
- 문서: `docs/MECHANICS.md`(수식 레퍼런스), `docs/BACKLOG.md`(보류 목록 — 여기 있는 건 의도적으로 미뤄 둔 것).

## 2. 게임 철학 (모든 판단의 기준)
- 본게임은 **무한 도전**(뱀서라이크). +20 까지는 튜토리얼, 파괴돼도 복구가 쉬움.
- 무기는 "저점을 받치고 고점을 더 밀어주는" 역할. 후반의 폭발적인 재미는 **빌드(카드·특성·속성 시너지)** 가 책임진다. 플레이어 쪽 상한은 두지 않는다(시즌제로 순환).
- **아무거나 골라도 재미있어야 한다**: 서툰 사람·어린 유저도 충분한 액션감과 적당한 파워(저점 보장).
- 유저 기준선: 일반 +25, 헤비 +30, 엔드 +31~35.

## 3. 작업 규칙
1. **이 프로젝트와 무관한 것을 섞지 마세요.** 작업하는 컴퓨터/계정의 다른 프로젝트, 개인 취향·전역 지시(코딩 스타일, 선호 프레임워크, 서명, 이모지·주석 규칙 등)는 적용하지 않습니다. 근거는 이 저장소 안의 내용뿐입니다.
2. **외부 의존성·CDN·API 추가 금지** (단일 HTML 유지). 새 설정 파일(`AGENTS.md`, `.codex/`, `package.json`, lock 파일 등)도 만들지 마세요.
3. **코드 스타일은 기존 파일을 따릅니다**: 촘촘한 한 줄 스타일, 짧은 영어 소문자 주석, 게임 화면 문구는 한국어.
4. **같이 하기(멀티) 통신 형식을 바꾸면 `MP_VER` 를 올리세요.** 저장 데이터(`S`) 형식을 바꾸면 `migrate()` 에서 예전 저장을 살리세요.
5. 수식·규칙이 바뀌면 `docs/MECHANICS.md` 를, 미루는 일이 생기면 `docs/BACKLOG.md` 를 같이 고치세요.
6. 바꾸기 전에 `node tools/reg.js` 로 기준을 확인하고, 바꾼 뒤 다시 돌려 **마지막 줄 `ERR []`** 를 확인하세요.
7. git/GitHub 작업(커밋, push)은 하지 마세요. 결과는 아래 형식의 zip 으로 돌려줍니다.

## 4. 주고받는 형식
- 받은 zip 의 `BASE.txt` 에 기준 버전(커밋 번호)이 있습니다. **작업 시작 전에 받은 그대로의 복사본을 `_base/` 에 보존**하세요(`_base/` 는 결과물에 넣지 않음, patch 기준용).
- 돌려줄 zip:

| 파일 | 내용 |
|---|---|
| 저장소 전체 (받은 구조 그대로, `_base/`·`node_modules/`·`tools/test.html` 제외) | 최종 결과 |
| `HANDOFF_BACK.md` | 무엇을 왜 바꿨는지(항목별), 변경 전·후 측정값, `reg.js` 결과, 남은 문제·질문, **작업 기록**(실행한 명령, 바꾼 파일 목록, 가정) |
| `patches/NN_짧은이름.patch` | **변경 하나당 patch 하나** (`diff -ruN _base 결과` 형식). 서로 의존하면 명시 |
| `patches/all.patch` | 전체 변경 |

- 받는 쪽은 patch 를 한 줄씩 검토해서 항목별로 받거나 버립니다. 그래서 변경은 작고 독립적으로 나눠 주세요.

## 5. 테스트 도구
```sh
npm i --no-save playwright && npx playwright install chromium   # 처음 한 번
sh tools/mk_test.sh      # tools/test.html 생성 (전역 변수 접근용 사본, 결과물에 넣지 않음)
node tools/reg.js        # 회귀 테스트 (1~3분), 마지막 줄 ERR [] 면 정상
node tools/dps.js 1 25   # 직업별 DPS: 허수아비 수, 강화 단계
```
`page.evaluate` 안에서 게임 전역(`S`, `B`, `G`, `startSurv`, `startEndless`, `svSpawn`, `svHit` 등)을 쓸 수 있습니다. 테스트 서버 전용 기능(`G.god`, `G.noSpawn`, `G.ts` 속도)도 있습니다.
