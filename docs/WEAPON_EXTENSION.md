# 무기 계통 추가 안내

기준: 426d349 + 버그 수정 + 계통 확장 구조 정리, 2026-10-10.
현재 직업 10개(공통 포함)와 무기 136개는 그대로다. 새 계통을 실제 추가한 문서가 아니라, 다음 작업에서 수정해야 할 정의와 검증 절차다.

## 1. 등록할 정의

모두 `index.html` 안에 있으며 외부 설정 파일이나 라이브러리는 필요 없다.

| 정의 | 등록할 내용 |
|---|---|
| `WL` | 계통 ID, 이름, 부모 `par`, 단계 `from/to`, 모양 `shape`, 설명·색·팔레트 |
| `WN` | 해당 구간의 단계별 무기 이름·설명·칼날 효과·팔레트. 단계마다 한 행 |
| `TRAITS` | 플레이어에게 보여 줄 특성 설명 |
| `CLASS_RULES` | 실제 공격 방식·기본 수치·고유 능력·전용 카드 자격. 부모와 같은 값은 생략 가능 |

`KIDS`, `WORDER`, `WEP`, `ATK_R`는 위 정의에서 생성한다. 자식 목록·도감 위치를 따로 등록하지 않는다. 코드를 수정한 뒤 페이지를 새로 열어 사용한다.

## 2. 부모·단계·저장 호환성

- 공통 루트는 `c` 하나다. 다른 계통은 실제 존재하는 부모를 지정한다. 순환 연결은 금지한다.
- 자식의 `from`은 부모의 `to + 1`이다. 최종 직업의 `to`는 `MAX`(현재 35)여야 한다. 같은 부모의 형제들은 같은 단계에서 선택한다.
- 예를 들어 3차 전직을 +30에 만들려면 중간 직업의 구간을 +20~29, 새 자식을 +30~35로 나눈다. 이 경우 **기존 +30~35 무기·보관함·도감·최고 기록의 이전 정책을 먼저 정해야 한다.** 이번 작업은 실제 단계 구간이나 저장 데이터를 옮기지 않았다.
- ID는 영문·숫자·`_`·`-`를 사용한다. `계통ID:단계`가 검 이력 SQL의 24자 제한 안에 들어가야 한다(현재 최대 단계 35이므로 ID 최대 21자).
- 전직은 `jobOptions()`로 현재 부모의 자식을 찾아 선택한다. `needsJob()`은 선택이 필요하면 다음 깊이(1, 2, 3...), 아니면 0이다.
- `lineAt()`은 단계에 맞는 조상으로 내려가고, `familyOf()`는 공통 바로 아래의 계열을 찾는다. 직업 ID의 글자 수에는 의존하지 않는다.
- 기존 ID를 유지한 채 직업을 추가하는 경우 저장 형식은 같다. ID 삭제·변경, 부모 이동, 구간 재편은 `migrate()`에서 장착·보관·도감·최고 기록 등을 함께 검토한다.

## 3. 수치와 능력 계승

`classRules(line)`은 공통→부모→자식 순서로 설정을 합친다. 일반 값은 자식 값으로 **교체**한다. 예를 들어 대검의 `hp: 90`, 성기사의 `hp: 110`은 기본 체력에 각각 +90, +110이라는 뜻이다. 성기사에 `hp: 20`을 쓰면 부모에 +20이 더해지는 것이 아니다.

- `atk`: 물리/마법 공격력 비율. 체력 `hp`, 이동 `speed`, 피격 배수 `taken`, 치명타 `crit`, 필살 충전 `fever` 등을 같은 곳에서 설정한다.
- `attack`: 기존 방식 `swing`(앞쪽 베기 또는 `spin: true` 회전), `stab`(근접 단도), `throw`(투척), `cast`(범위 마법) 중 선택한다.
- `cd`, `reach`, `reachLv` 등은 공격 주기·범위를, `dashMax/dashCd/dash/dashInv` 등은 회피를 정한다.
- `rage`, `killHeal`, `shield`, `execute`, `dashSlash`, `volley`, `fireField`, `chain` 등으로 이미 구현된 고유 능력을 재사용한다. 능력 객체는 통째로 교체하므로 필요한 필드를 모두 넣는다. 사용하지 않을 상속 능력은 `null`로 끈다.
- `cards`는 조상과 자식의 목록을 합쳐 중복을 제거한다. 기존 전용 카드의 등장 조건을 재사용하며, 카드 수치나 내용을 바꾸지는 않는다.
- `elements`는 원소별로 덮어쓴다. 상속된 보너스를 없애려면 해당 원소를 0으로 지정한다.
- `TRAITS`는 설명뿐이다. 실제 능력은 `CLASS_RULES`와 일치시킨다. 부모 설명을 바꾸려면 `WL`의 `traitReplace`에 기존 설명의 콜론 앞 제목을 지정한다. 비도술사는 `날렵함`을 제거하고 `연무`를 넣는다.

모양은 현재 `common/great/twin/magic` 중에서 재사용할 수 있다. 공격 설명은 실제 공격 방식에서 찾으므로 모양과 공격이 달라도 된다. 완전히 새로운 모양은 `genSword`, 새로운 공격 알고리즘은 `ATTACKS` 및 피해·그리기·필요한 멀티 효과 코드를 구현해야 한다. 새 이름과 설명을 입력하는 것만으로 새로운 공격이 만들어지지는 않는다.

## 4. 도감과 선택 화면

게임 도감은 부모 관계·깊이로 배치한다. 많은 가지가 생기면 스크롤 목록으로 전환한다. 직업 선택창과 긴 무기 설명도 스크롤되며 화면 밖 항목의 클릭 영역은 잘린다.

별도 「모팔모의 전투 도감」 HTML은 게임 실행 파일과 다른 문서다. 실제 직업을 추가할 때 그 문서의 설명·직업 카드·이미지도 별도로 최신화한다.

## 5. 추가 후 확인

1. 기존처럼 `sh tools/mk_test.sh`로 검사 사본을 만든다. 검사 사본의 콘솔에서 `validateWeaponTree()`와 `validateClassRules()`를 실행한다. 두 결과가 모두 `[]`여야 한다. 검사 함수는 일반 플레이나 저장 데이터를 바꾸지 않는다.
2. `node tools/reg.js`가 마지막에 `ERR []`를 출력하는지 확인한다.
3. 추가 계통으로 전직, 전투, 구르기·특수 능력, 보관/꺼내기, 저장 후 재접속, 단계 하락과 재선택을 확인한다.
4. `node tools/dps.js 1 25`, `node tools/dps.js 5 25`로 비교한다. 등록된 모든 계통을 자동으로 순회하고 요청 단계를 각 계통 구간 안으로 맞춘다. 출력되는 실제 단계를 확인해 같은 조건으로 전후를 비교한다.
5. 도감·선택창의 모든 직업을 좁은 화면에서도 볼 수 있고 선택할 수 있는지 확인한다.
6. `docs/MECHANICS.md`와 별도 전투 도감에 반영한다. 새 효과의 멀티 통신 형식이 바뀌면 `MP_VER`를 올린다. 형식이 같더라도 새 직업을 모르는 구버전과의 호환성은 별도로 점검한다.

이번 구조 정리에서는 저장 형식과 `MP_VER=17`을 유지했다. 온라인 서버·실제 두 기기의 플레이 검증은 별도이며, 테스트용 추가 직업들은 전달하는 게임에 포함하지 않았다.
