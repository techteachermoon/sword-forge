## 1. 게임 소개 (필요한 만큼만)

- 「검 강화하기」: 단일 파일 HTML 캔버스 픽셀 게임 (`index.html`, 약 5,000줄). 검을 강화(+0~+35)하고, 그 검으로 뱀서라이크 전투(원정 / **무한 도전**)를 합니다.
- **본게임은 무한 도전**: 카드·특성·속성 시너지로 빌드를 쌓아 더 깊은 층을 뚫는 재미. +20까지는 사실상 튜토리얼(30분 안팎이면 도달, 파괴돼도 복구가 쉬움).
- 유저 기준선: 일반 유저 **+25** 전후, 헤비 유저 **+30**(며칠), 엔드 +31~35.
- **게임 철학**
  - 무기는 "저점을 받쳐주고 고점에서 더 나아가게" 해주는 역할. 후반의 폭발적인 재미(뽕맛)는 **빌드**가 책임진다.
  - **아무거나 골라도 재미있어야 한다**: 게임에 서툰 사람·어린 유저가 막 골라도 충분한 액션감과 적당한 파워가 나와야 한다(저점 보장).
  - 상한을 두지 않는다(시즌제로 밸런스 순환 예정).

## 2. 점검 범위: 무기 계통

| 무엇 | 코드 위치 (`index.html` 에서 검색) |
|---|---|
| 계통 트리: 공통 c(+0~9) → 대검 g / 단도 t / 마검 m (+10~19) → 2차 직업 g1 광전사·g2 성기사 / t1 암살자·t2 비도술사 / m1 화염술사·m2 뇌전술사 (+20~35) | `const WL`, `lineAt`, `wepOf`, `buildWeps` |
| 직업 선택 시점과 흐름 (+10, +20) | `needsJob`, `chooseJob`, 직업 선택 모달(`k: 'job'`) |
| 계통별 고유 특성 문구와 실제 효과 | `const TRAITS`, `traitsOf`, `CLS_INFO`, `tr(` 사용처 |
| 계통별 전투 기본 수치: 체력 보정, 이동, 구르기, 공격 주기, 범위 | `startSurv` 안의 `B.P.max`, `svCd`, `svR`, `svDash`, `svDashCd` |
| 계통별 기본 공격 방식 | `svSwing`(대검·공통), `svStab`(단도), `svThrow`·`svVolley`(비도술사), `svCast`·`svLaunch`·`svBlast`(마검 계열), `svUpdateSwing` |
| 물리/마법 공격력 비율 (임시 값) | `const ATK_R`, `pAtk`, `mAtk`, `atkFor` |
| 무기 이름·모양·칼날 속성(단계별) | `SW`, `WEP`, `wfx`, `FXE` |

**확정된 것 (바꾸자고 하지 말 것)**
- 무기 공격력 곡선 `ATK(L)`: +20에서 800, 그 아래 단계당 ×1.12, 위 ×1.10.
- 피해 = 공격력 × 공격 계수 × 방어 보정. 피해 종류 물리/마법/고정, 방어는 `100/(100+방어)`.
- 치명타: **물리 기본 공격만**, 단도 계열 기본 25%, 배수 2.
- 수식 전체는 `docs/MECHANICS.md` 1~2절 참고.

**범위 밖 (나중에 따로 갈아엎을 예정 — 언급만, 제안은 하지 마세요)**
- 전투 카드(`SVC`), 인챈트(`ENCH`), 무한 도전 특성(`ENT`), 속성·융합, 던전/스테이지 밸런스, 강화 확률·경제.
- 이미 알고 있는 문제 목록은 `docs/BACKLOG.md` 에 있습니다. 거기 있는 건 "알고 있음"으로 짧게만 적어 주세요.

## 3. 봐 주었으면 하는 질문

1. **역할 구분**: 9개 계통(대검·단도·마검과 2차 6개)이 플레이 감각·역할에서 서로 확실히 구분되는가? 겹치거나 존재감이 약한 계통은?
2. **첫 선택의 재미**: +10, +20 직업 선택이 "고르는 맛"이 있는가? 선택 화면 문구만 보고 차이를 이해할 수 있는가(전연령 기준)?
3. **저점 보장**: 아무 계통이나 골랐을 때 액션감·파워가 충분한가? 특히 너무 약하거나 답답한 계통은?
4. **기본 성능 밸런스** (카드 없는 상태): 아래 DPS 측정을 근거로, 계통 간 격차가 의도로 설명되는 수준인가? 단일 대상/다수 대상 차이도.
5. **문구와 실제 효과 불일치**: `TRAITS`·`WL[].d`·`CLS_INFO` 설명과 코드 동작이 다른 곳.
6. **물리/마법 비율 `ATK_R`**: 계통 성격에 맞는 값 제안(근거 포함). 지금 값은 임시.
7. **버그**: 계통 관련 코드에서 발견한 실제 버그(재현 방법 포함).

각 항목마다 **근거(코드 줄, 측정값)** → **문제** → **선택지 2~3개** → **추천** 순서로 써 주세요. 확신이 없는 건 "추정"이라고 표시해 주세요.

## 4. 테스트 방법

```sh
npm i --no-save playwright && npx playwright install chromium   # 처음 한 번 (repo에 파일 추가 금지: --no-save)
sh tools/mk_test.sh            # tools/test.html 생성 (게임 전역 변수 접근용 사본, 커밋 금지)
node tools/reg.js              # 회귀 테스트, 마지막 줄 'ERR []' 이면 정상 (1~3분)
node tools/dps.js 1 25         # 허수아비 1마리, +25 직업별 DPS (2분 안팎)
node tools/dps.js 5 25         # 허수아비 5마리 (다수 대상)
```

참고 측정값 (+25, 허수아비 1마리, 카드·인챈트 없음, 방어 0):
`공통 464 · 대검 1,613 · 광전사 3,192 · 성기사 2,912 · 단도 3,896 · 암살자 5,663 · 비도술사 10,072 · 마검 3,167 · 화염술사 8,475 · 뇌전술사 6,162`
(공통은 +9, 1차 직업은 +19 로 측정되어 단계가 다름. 랜덤 때문에 ±10% 흔들림)

직접 실험할 때는 `page.evaluate` 안에서 게임 전역(`S`, `B`, `G`, `startSurv`, `svSpawn`, `svHit` 등)을 쓸 수 있습니다. `tools/dps.js` 가 예시입니다. 실험 스크립트는 repo 밖(임시 폴더)에 두세요.
